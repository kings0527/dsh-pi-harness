# 从重复推理转向可验证的实验搜索

## 判断

需要做的是“以证据管理求解分支的调度器”。模型可以提出新假设、报告卡点和建议换模型；外部 runtime 控制实验租约、模型路线、预算和证书提交。仅依赖模型求助，会受自评偏差影响；仅依赖轮数，会把等待、真实探索和原地打转混在一起。

### 1. 机制层：API 控制不到神经专家

MoE 的 expert 是模型内部的前馈网络组件，router 按每个 token 的隐状态分配计算；不是一个可命名的“逆向工程专家代理”。Attention 负责信息交互，MoE router 负责条件计算，外部 agent 路由负责选择整个求解器。这三个层次不能混为一谈。

改变提示词和输入证据可能改变内部激活，但通过常规 API 无法指定专家编号、保证激活不同专家，或判断某些专家已经用尽。采样温度改变输出分布，也不等于遍历专家。自行部署能修改 router 并记录激活，但强制 top-k、扩大激活或绕过门控可能破坏训练形成的分工；专家使用率最大化没有自动等价于解题成功率最大化。

所以工程接口应该承诺“可审计的策略多样性”，不能承诺“唤醒隐藏专家”。这个思路同样适用于 dense 模型。

### 2. 概率层：失败时间不能证明已经穷举

同一个模型连续失败一天，换另一个模型半天成功，至少同时改变了模型、随机轨迹、上下文、已有工具发现和累计探索成本。不能仅凭这一个顺序实验识别因果。

只有在独立同分布、单次成功率 p 固定的假设下，N 次尝试至少成功一次的概率才是 `1-(1-p)^N`。现实 agent 往往反复用同一假设，失败高度相关；N 可以增加，而有效搜索覆盖几乎不变。反之，一条经过验证的新阴性结果，虽然没有“解决”，仍可显著缩小搜索空间。

可操作的判断是：“在当前证据与策略下，继续花资源的边际收益是否低于另一个实验配置？”不是“这个模型的所有能力是否已经穷尽”。

### 3. 搜索层：变化必须落在实验上

每次尝试用一个结构化定义：

```json
{
  "hypothesis": "哪一个可证伪的解释",
  "intervention": "改哪个条件、保持哪些变量不变",
  "expectedObservation": "若假设成立/不成立，各会看到什么",
  "oracle": "由什么工具或复现实验证明",
  "evidenceVersion": "基于哪批事实",
  "method": "从何种表征或推理方向切入",
  "modelRoute": "provider/model/effort"
}
```

| 可改变维度 | 对安全分析的具体含义 | 为何有用 |
|---|---|---|
| 假设 | 输入未到达危险点 / 已到达但约束不可满足 / 环境不匹配 | 改变因果解释 |
| 表征 | 源码、反汇编、控制流、状态机、输入输出轨迹 | 使不同约束可见 |
| 推理方向 | 输入前推 / 从失败条件逆推 | 改变搜索顺序 |
| 实验 | 最小复现、单变量对照、反例、回归 | 产生可区分的观察 |
| 信息 | 补一个版本条件、真实返回值、调用栈 | 改变可用证据 |
| 求解器 | 换模型、同模型新上下文、不同推理预算 | 改变先验与搜索能力 |

单纯把“你是专家”换成“你是资深专家”，没有定义新的实验。新模型也可以复用同一个错误假设，因此多样性必须在报告和产物中体现。

### 4. 层次层：逻辑嵌套与代理嵌套可以分开

主线应保留：当前目标、已验证里程碑、前提引用、依赖版本、当前阻塞点。副本保留：候选假设、尝试路线、完整日志、阴性结果、原始证据。工作树或调试器状态是另一个维度，不由对话分离自动解决。

一个子问题可以继续拆成多个逻辑节点，但不需要每层代理重新总结给上一层。所有节点写入同一个有原文引用的证据图，由一个调度器向叶子发放实验租约。子任务读取原始 contract、依赖证书和相关证据，而不是上一层对上一层摘要的再摘要。

这使主线只看到一个卡片：“步骤 8 的出口经 check X 验证；结论 Y；证书 SHA256 Z；局限 L”。需要展开时通过引用读取原件。摘要是导航，不是替代证据。

**前面的 1—7 不能永久冻结为真。** 它们是有条件、可撤销、带版本的结论。第 8 步可能证明第 5 步的环境假设错了；系统必须使依赖旧证书的节点失效并回溯。否则只会把错误更整齐地封装起来。

### 5. 约束层：外部 runtime 拥有提交权限

状态机是 `open → running → accepted | blocked | error | cancelled`；旧依赖失效时对外显示 `stale`。worker 只有求解和报告能力；进入主线的提交必须通过当前验收器、当前依赖版本和当前租约。

记录“语义结论”归模型，检查身份、重复配置、字节完整性、预算、退出码、验收结构和依赖版本归代码。不能用“summary 看起来像完成”作为提交条件。也不能仅看到不同文本就认定进展。

`goal` 驱动必须识别“这个阻塞点没有可续租的实验”，不能在外层不断发一句继续，从而重置内部预算。v0.1 通过 `blocksMainline` 显式绑定与 `goals.block()` 实现；没有把副本通过误当成整个 goal 完成。

预算还需跨副本共享。v0.1 的 `maxSessionAttempts` 累计同项目同 session 的全部 case，避免用新 ID 绕过单副本上限。这不计量插件之外 root agent 的开销，也没有声称是完整的账户费用限制。

### 6. 激励层：不给模型自评制造错误收益

即使模型没有主观意图，运行协议也会形成选择压力：若说“我不会”立即得到更强模型，弱模型可能过早移交；若必须说“我搞定了”才能结束，可能产生虚假完成；若要求“必须发现新东西”才能续跑，可能制造新名词和噪声日志。

缓解方式是让完成、进展和资源申请走不同字段。资源分配看外部验证的观察及任务价值，不看语气、道歉、主观信心或疲惫叙述。异常等待和网络故障先修执行环境；任务被拒绝也不当成能力不足自动转给别的模型重试。

## 建议的下一阶段

先收集至少一批有固定入口、固定验收器的真实历史阻塞案例。对每例做四臂对照：Flash 原轨迹继续、Flash 新上下文同方法、Flash 新上下文换方法、GLM 新上下文同入口。分配相近的 token/费用预算，工具权限、仓库版本和验收器一致；重复不同采样，不把接力后累计发现归功于单个模型。

指标：验收成功率、首次正确结果的 token/费用/时间、新验证观察数、重复假设率、错误提交率、主线新增上下文、依赖失效后的恢复是否正确。工具等待单独计时。样本少时报告原始结果和不确定性，不把几个案例拟合成精确的“能力上限概率”。

随后才值得做“每单位成本的预期可验证信息增量”调度：按任务类型和入口状态估计某种模型/方法是否值得继续。可以使用带不确定性的 contextual bandit，但其奖励必须锚定外部验收和有用的阴性结果，不能奖励语言新颖度、token 数或自评分数。

语义去重应比较“假设—干预—预测—观察”及其证据版本。向量相似度只能找候选重复；同一个判断模型也会有盲区。对高代价实验，要求候选实验明确说明它如何区分尚存的两个解释，比要求“再想一种方式”更可检验。

并行化之前增加工作区适配：代码用独立 worktree/容器，调试工具用独立进程与状态快照，服务和数据库使用可恢复的测试实例。只把被独立复现的 artifact/patch 提交主线，不能把共享工作目录里的多路修改当成实验隔离。

## 代码观察与来源

- `pi-harness` 检查提交：`aae5991306636dd7cf0afc4396439e29cd87dbe6`。`core/spawn/index.ts` 已支持 model 字段，但普通 `extensions/spawn.ts` 的 run schema 没有暴露每个 worker 的模型；普通 run 将完整 stdout/stderr 回传父上下文。已有 Board 溯源和结构化结论机制值得复用，但不能让每条副本日志都成为根会话的常驻材料。
- `dsh-pi-harness` 检查提交：`1c16096887f7051599e0f468adb87411a683cf38`。`lib/reference.js` 默认枚举所有 active topics；因此单纯新开多个 topic 不自动产生主线/副本隔离。本插件将原始实验置于独立账本，并在受管理 worker 上过滤该桥接器的被动 reference。
- DSH 上游检查提交：`687f282e8625c6b8d11ff58211a90524be2e4317`。`packages/subagent/subagent/src/types.ts` 的 `startActivation / delivery:'caller' / agentOptions / outputSchema`，fresh spawn provider，以及 `packages/goal/goal/src/index.ts` 的 `goals.block()` 提供接入点。
- [DeepSeek API](https://api-docs.deepseek.com/api/create-chat-completion/)：可配置模型、推理与生成等参数，没有公开指定 MoE 专家编号的调用字段。
- [DeepSeek V3 推理代码](https://github.com/deepseek-ai/DeepSeek-V3/blob/main/inference/model.py)：历史公开实现可用于理解 router 基于 token 隐状态选择 expert 的层次；不能据此断言 Flash 当前版本的全部内部结构。
- [GLM-5.3 文档](https://docs.z.ai/guides/llm/glm-5.3)：当前文档描述推理 effort；厂商 benchmark 不能代替用户任务的受控对照。
- [DSH subagent 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/subagent.md)。以上外部接口检查于 2026-10-21，DSH API 尚未稳定，安装前需核对本机版本。
